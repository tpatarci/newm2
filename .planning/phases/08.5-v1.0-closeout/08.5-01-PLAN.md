<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| X client → WM | The window title is client-supplied, server-allocated, arbitrary bytes, and now reaches a second consumer (the matcher) as well as the tab renderer |
| Config file → matching | A title criterion decides which windows a rule's actions apply to |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-8.5-TITLE | Tampering | The `_NET_WM_NAME` read | medium | mitigate | The new type argument threads through the SAME bounded `getProperty_aux()` path: server-reported item count, existing length cap, embedded-NUL truncation retained. No new allocation path is introduced. Task 1 Test 4 pins non-ASCII handling; the ASan runs pin the leak. |
| T-8.5-SPOOF | Spoofing | A hostile client setting a title that matches another application's rule | low | accept | A client can claim any title, exactly as it can claim any WM_CLASS (T-8-SPOOF, accepted in 08-10). The consequence is bounded by the same three cosmetic actions — no decoration, a position, a taskbar hint — none of which grants capability. Titles are in fact *easier* to spoof than classes, since applications change them constantly; the accepted-risk reasoning is unchanged but the surface is wider, and that is worth stating rather than inheriting silently. |
| T-8.5-DOS | Denial of Service | Title matching on every managed window | low | accept | The fold is O(rules × criteria) once per window at map time, over a bounded string. A title change does not re-fold (D-8.5-03), so a client cannot drive matching work by renaming itself in a loop — the re-fold this plan declines to build is also the DoS vector it declines to open. |
| T-8.5-SHELL | Elevation of Privilege | The rule action set | high | mitigate | Unchanged: this plan adds a CRITERION and no action. The three shipping actions execute nothing, and the source-level grep guard over `src/Rules.cpp` still holds. |
</threat_model>
