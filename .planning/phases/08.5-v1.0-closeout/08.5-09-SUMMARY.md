## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `proc-state:` read from the state letter, not from the plan's literally-described field**

- **Found during:** Task 1 (capture tool)
- **Issue:** The plan's action text says to record `proc-state:` from "the third whitespace-separated field after the last closing parenthesis" in `/proc/<pid>/stat`. Read literally that is `pgrp` — a number, which could never match the `[Tt]` stopped-state gate and would therefore have passed that gate **vacuously** on every run. The gate exists to prove the instrument did not leave the observed process suspended (T-8.5-REPRO-04); a gate that cannot fail proves nothing.
- **Fix:** The tool records the **state letter** — the FIRST whitespace-separated field after the last `)`, which is field 3 of the line overall. That is the field that actually spells `S`, `R`, `T` or `t`.
- **Files modified:** `scripts/diag/wm-stack-capture.sh`
- **Verification:** Every committed bundle records `proc-state: S` after the debugger detached, and the mutation-adjacent reasoning holds because the value is now one the `[Tt]` gate can actually match.
- **Committed in:** `8623618` (Task 1 commit)

**2. [Rule 1 - Bug] Mutation row 3 must skip the helper's missing-channel ABSENT fallback as well as the capture-script invocation**

- **Found during:** Task 2 (mutation table)
- **Issue:** Row 3 as written skips only the capture-script invocation. But the helper's own missing-channel ABSENT fallback is itself a `must_haves` truth — every channel is PRESENT with content or ABSENT with a reason — so leaving it in place would have **re-synthesised the two missing channels** as recorded absences and masked the mutation entirely. The row would have gone green and measured nothing.
- **Fix:** Row 3 skips the capture-script invocation **and** the missing-channel fallback, leaving only the three channel lines the case writes itself.
- **Files modified:** `tests/test_wm_repro.cpp` (mutation only — reverted; the tree was confirmed clean before the measurement ran)
- **Verification:** The row reddens the calibration case at `3 == 5` — exactly the "three lines rather than five" the plan predicted — in both the debug tree and through the ASan gate.
- **Committed in:** not committed; mutation rows are reverted by design, and `git diff --stat -- src include tests/test_wm_runtime.cpp` printed nothing afterwards.
