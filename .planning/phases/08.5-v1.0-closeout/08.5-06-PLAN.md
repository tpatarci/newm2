**The counters, in `include/Manager.h` beside `int m_currentTime;` (:215).** Four private members following the file's `m_` + camelCase convention: a count of cold-cache branch entries, a count of those entries that had to block (nothing matching was already queued), a count of waits satisfied by an event that was not the window manager's own root append, and the longest single blocked wait in milliseconds. Initialise all four in `src/Manager.cpp`'s constructor initialiser list in header declaration order.

**The instrumentation, in the cold-cache branch of `WindowManager::timestamp()` (`src/Manager.cpp:917-924`).** Keep the `XChangeProperty` append exactly as it is. Then, instead of going straight into the blocking wait, take the non-blocking check form first — the codebase already uses `XCheckMaskEvent` for exactly this shape at `src/Events.cpp:539`. It removes a matching event from the queue if one is there and returns without blocking if none is. That makes the two cases separable and is semantically identical to what the blocking call would have done with an already-queued event:

- Count the branch entry unconditionally.
- If the check form returned an event, no wait happened. Fall through to the classification below.
- If it did not, this is a real block. Count it. **On the first blocked wait only**, print `wm2: timestamp: entering blocking property wait` to stderr *before* entering the wait, so a wait that never returns still leaves a record — a window manager blocked in a mask wait burns no CPU and is indistinguishable from a healthy idle loop from outside, which is why the record has to be written on the way in rather than on the way out. Then take a `std::chrono::steady_clock` reading, perform the wait exactly as the current code does, take the second reading, and update the longest-wait member. If that single wait exceeded 100 ms, print `wm2: warning: timestamp: blocking property wait ` followed by the elapsed milliseconds — a warning, per the project's error-handling convention, never `fatal()`.
- **Classification, on both paths.** If the matched event's window is not `m_root` or its atom is not `Atoms::wm2_running`, count a foreign match and, **on the first occurrence only**, print `wm2: warning: timestamp: property wait matched a foreign event`. This is the half of the mechanism that says a client's own property change can be consumed and discarded before `eventProperty()` ever sees it. Clients carry `PropertyChangeMask` (`src/Client.cpp:106`, `:1524`), so the possibility is real; whether it happens is what this counter answers.
- `m_currentTime = event.xproperty.time;` is unchanged.

**Security constraint, and it is not optional.** Every line printed here is a fixed ASCII state word plus an integer. No window id, no atom name, no window title, no host name, no environment value.
