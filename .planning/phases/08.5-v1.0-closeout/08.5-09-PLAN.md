Two modes.

`--probe` writes a capability report to stdout and exits 0 unconditionally. On this host, checked while this plan was written: a debugger is present at `/usr/bin/gdb` (GNU gdb 12.1), `ptrace_scope` reads `1`, and `/proc/<pid>/wchan` is readable and returns a kernel symbol. `<pid> <dir>` is the capture mode, and its first act is refusal, not capture. Validate the output directory before writing: require an absolute path, refuse any path containing a parent-directory component, and create it with `mkdir -p`. There is no fixed temporary-directory name anywhere in the file.

Then capture, appending to `capability.txt` in the output directory and writing two sibling files. `wchan.txt` gets the contents of `/proc/<pid>/wchan`; a literal `0` means the task was running rather than sleeping and is recorded as read, not treated as absent. `backtrace.txt` gets the output of a single batch debugger invocation against the PID issuing exactly one command, `thread apply all bt`.
