<objective>
Close the event loop's readiness-ordering defect, its unguarded `XNextEvent()` on
bare `POLLIN`, its busy spin on a failed descriptor, and its never-consumed exit
flag — each proved by a case that fails at the pinned round base and passes after
the fix.

**Why this round is shaped differently from the three before it.** Plans 08.5-06,
08.5-09 and 08.5-10 tried to attribute a reparent wedge statistically: eight
full-suite samples, then five hang-time backtraces, then a two-arm intervention
over 8000 window maps producing 129 trips and 40 evidence bundles. That chain
cost three rounds and three operator rulings and ended without a mechanism. A
line-by-line read of `WindowManager::nextEvent()` against the Xlib contract, plus
one forty-line probe, produced the mechanism and a deterministic reproduction in
seconds. An X11 event loop is deterministic; verifying one stochastically is a
category error, and this round replaces the instrument rather than taking a
fourth turn with it.

**The defect, as measured rather than as hypothesised.** The earlier account held
that events were stranded in libxcb's transport queue, invisible to both
`QLength()` and `poll()`. That account was tested and is **false on this host**: a
round trip transfers such events into Xlib's own queue, where `QLength()` sees
them. The real defect is an ordering error and needs no transport subtlety:

1. `src/Events.cpp:195` tests `QLength(display())`. Empty; branch not taken.
2. `src/Events.cpp:201` calls `XFlush()`. On this libX11 the flush path polls the
   transport — `_XFlush` reaches `xcb_poll_for_event` / `xcb_poll_for_queued_event`
   — and **moves the pending event into `dpy->qlen` while draining the socket.**
3. The code does not re-test `QLength()`.
4. `src/Events.cpp:205` calls `poll()` with `timeout = -1` whenever no focus timer
   is armed. The socket is empty. **Nothing will ever wake it.**

Measured, replaying exactly those lines:

```
line 195  -> QLength=0   (branch NOT taken)
          -> fd readable=1
line 201  -> XFlush() called
line 205  -> QLength=1, fd readable=0     *** WEDGE ***
```

That probe is committed at `evidence/gates/eventloop/wedge-probe.c` and is this
round's reference reproduction. Note in particular that it synchronises connection
A and queues no further output on A before the flush, and the wedge still
reproduces: on this host the flush polls the transport even with an empty output
buffer. Task 2's pump case follows that sequence.

**This explains every reading the three measurement rounds produced**, which is
the strongest available check that it is the right mechanism and not merely a real
one: all five round-3 backtraces named `poll(nfds=2, timeout=-1)` at `:205`,
because that is where it wedges; the round-4 control clients never framed even at
the hard 8000 ms deadline, because nothing can wake that poll; the round-4
intervention clients framed in 20–45 ms, because any delivered event makes the
socket readable and the queued backlog then drains oldest-first; `recvq` read 0 in
all 40 bundles, because `XFlush()` had drained the socket; and the healthy
calibration bundle showed the same frame as the trips, because an idle window
manager is legitimately in that same poll — which is exactly why no backtrace
could have separated the two.

**The structural obstacle this plan must solve first.** The predicate at `:195` is
an inline expression inside a non-static member of a class whose constructor opens
a display and takes the root window. No test can reach it. `test_eventloop` links
`Catch2::Catch2WithMain` and `PkgConfig::X11` with `include/` on the header path
and no production objects (`CMakeLists.txt:206-215`); the `test_wm_*` binaries are
black-box and spawn the built window manager, which reintroduces exactly the
timing dependency this round exists to eliminate. So Task 1 extracts the decision
to a header-only surface **faithfully, preserving the defect**, and Tasks 2 and 3
then run red-then-green against it.

**What this round does not claim.** It does not claim the release gate is now
reliable. That is a rate, and this round measures none.
</objective>
