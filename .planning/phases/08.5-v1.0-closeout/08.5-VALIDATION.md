## Sampling Rate

- **After every task commit (during the fix):** `ctest --test-dir build/debug -L '^wm_config_runtime$' --no-tests=error`, plus the two new bounded-wait cases. Seconds, not minutes.
- **After every plan wave:** one full `bash scripts/gates/build-all.sh debug` (~4 min).
- **Attribution gate (end of the instrument-and-attribute plan):** one **red** run captured *with* WM stderr present in the failing case's output, committed.
- **Fix gate (end of the fix plan):** **10 consecutive green** `bash scripts/gates/build-all.sh debug` runs — operator-selected 2026-08-30 — each with `uptime`, `free -m` and orphan-`Xvfb` count recorded beside it, committed as a per-run table. No run omitted, no retry.
- **Phase gate (the 08.5-04 retry):** all three trees plus static analysis green in **one** pass at the final commit, captured into `evidence/gates/` with `PROVENANCE.txt`.
- **Before `/gsd-verify-work`:** full suite must be green.
- **Max feedback latency:** ~240 seconds (one full debug run).

### Why 10, and what it buys

Baseline is a measured red-run rate of **0.40** (2 red of 5 —
`evidence/gates/flake-measurement/README.md`). Five observations is a small
sample; the honest reading is "around 40%, wide uncertainty". If the true
post-fix red rate were still `p`, the probability of N consecutive greens is
`(1-p)^N`:

| N consecutive green runs | If p = 0.40 (unfixed) | If p = 0.10 (mostly fixed) |
|---|---|---|
| 3 | 0.216 | 0.729 |
| 5 | 0.078 | 0.590 |
| 8 | 0.017 | 0.430 |
| **10 (selected)** | **0.006** | **0.349** |

At the measured baseline, 10 consecutive greens is a ~0.6% chance of occurring
by luck. ~40 minutes of wall time.

## Negative-Result Contract

If the instrumentation shows the WM never enters the blocking `XMaskEvent`
branch, that **refutes** the research's leading hypothesis (`src/Events.cpp:20`
→ `src/Manager.cpp:913-927`). That is a success of the method, not a failure of
the plan. The refutation is committed with the same weight as a confirmation,
and the phase re-plans from the next named candidate — deferred item 17's
`findOpenMenu()` fallback reaching case 198 through the unverified menu helper,
fixture teardown races, or host memory pressure.

An attribution is withheld when the measurement does not support one. That is
the pattern plan 08.5-04 established and it is not relaxed here.
