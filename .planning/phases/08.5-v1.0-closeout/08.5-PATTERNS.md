## Pattern Assignments

### `tests/test_wm_runtime.cpp` — new bounded-wait regression case (test, deadline-as-assertion)

**Analog:** `tests/test_wm_state.cpp:1685-1739` — "An oversized property array is
read within a bound and does not hang", tag `[wm_props]`.

This is the only case in the suite whose *claim* is "the WM did not hang", which
is exactly the new case's claim. Copy its shape, not just its imports.

**Fixture + display opening (lines 1687-1692):**
```cpp
    WmFixture fixture;
    x11::DisplayPtr dp = fixture.openDisplay();
    REQUIRE(dp != nullptr);
    Display* d = dp.get();
    parkPointer(d);
```

**The deadline-is-the-assertion core (lines 1719-1730) — copy this verbatim in
structure:**
```cpp
    // The deadline is the assertion. A WM that read the whole array, or that
    // looped over 200,000 items doing X round trips, would still be "alive"
    // when this expires -- and that is precisely the failure being excluded.
    const auto start = std::chrono::steady_clock::now();
    const Window frame = awaitFrameFor(d, win, 15000);
    const auto elapsedMs = std::chrono::duration_cast<std::chrono::milliseconds>(
                               std::chrono::steady_clock::now() - start).count();
    INFO("framing took " << elapsedMs << " ms");
    INFO("wm stderr:\n" << fixture.wmStderr());
    REQUIRE(frame != None);
    CHECK(elapsedMs < 10000);
```

Note the two-tier deadline: the *poll* deadline (15000) is generous so a loaded
host does not flake, and the *assertion* deadline (10000) is tighter. The new
bounded-wait case must use the same two-tier split, sized against whatever bound
the fix installs in `timestamp()`.

**Liveness tail (line 1739):**
```cpp
    REQUIRE(fixture.wmAlive());
```
Load-bearing here: a WM blocked in `XMaskEvent` burns no CPU and *is* alive, so
`wmAlive()` alone can never be the assertion — it is the control that separates
"stalled" from "crashed".

**Second analog for the elapsed-time reporting loop** — `tests/test_wm_runtime.cpp:1735-1741`,
same file the new case lands in:
```cpp
    for (const Path& p : paths) {
        INFO("path: " << p.name << " elapsed=" << p.result.elapsedMs << "ms"
             << " exit=" << p.result.exitCode
             << "\noutput:\n" << p.result.output);
        CHECK_FALSE(p.result.timedOut);
        CHECK(p.result.elapsedMs < kFatalDeadlineMs);
        CHECK(p.result.exitCode != 0);
    }
```

**Wall-clock spacing helper to use, never a tight loop** (`tests/test_wm_runtime.cpp:192-199`):
```cpp
// A deliberate wall-clock interval, used only where the elapsed time is itself
// the thing under test (the long press against destroy-window-delay). Spelled
// as a deadline loop rather than a blocking call so it matches the rest of the
// file's waiting discipline and never blocks the input driver's connection.
void holdFor(int ms)
{
    const auto until = Clock::now() + std::chrono::milliseconds(ms);
    while (Clock::now() < until) pollSleep();
}
```

**Settle helper** (`tests/test_wm_runtime.cpp:182-189`) — fifteen *spaced* nudges,
never a tight `pumpWm()` loop:
```cpp
// Fifteen nudges at 20ms intervals -- the shape tests/test_wm_focus.cpp arrived
// at after a TIGHT loop of the same length still read the stale value.
void settleWm(Display* d)
{
    for (int i = 0; i < 15; ++i) {
        pumpWm(d);
        pollSleep();
    }
}
```

**The D-33 convention block that governs every discovery call (`CMakeLists.txt:121-148`),
abridged verbatim:**
```
    # D-33: TAG SELECTION CONVENTION -- applies to every test-discovery call in
    # this file, no exceptions.
    #
    # Catch2 registers each ctest test under its TEST_CASE *name*, so a Catch2
    # tag is invisible to `ctest -R` (which matches names). A tag-shaped -R
    # expression matches zero tests, and ctest exits 0 on zero matches -- making
    # every such gate green-on-nothing. The tags-as-labels option (Catch2 v3.14
    # extras/Catch.cmake:152) registers the tags as ctest LABELS ...
    #
    # Consequently, every gate in Phase 8 selects by ANCHORED label and always
    # passes --no-tests=error:
    #     ctest -L '^wm_process$' --no-tests=error
    #     ctest -L '^(wm_lifecycle|wm_sizehints|wm_gravity)$' --no-tests=error
    # Anchoring is load-bearing: -L is an unanchored regex, so a bare
    # `-L config` would also drag in `wm_config_runtime`. --no-tests=error is the
    # backstop that turns a mistyped or renamed tag into exit code 8 instead of a
    # silent pass.
```

**Two consequences the planner must carry into task text:**

1. **No CMake edit is required** if the new cases carry an existing tag of
   `test_wm_runtime` (`[wm_config_runtime]`, `[wm_tablabel]`, `[wm_errors]`,
   `[wm_stress]`). If a *new* tag is introduced, the comment at `:625-626` ("the
   four tags this file carries") is a counted claim and must be updated with it.
2. **Every per-task verify command uses `-L '^tag$' --no-tests=error`, never `-R`.**
   A tag-shaped `-R` matches zero tests and exits 0.

Also note (`CMakeLists.txt:598-599`): `test_wm_runtime` allocates its own display
per fixture instance, so it deliberately carries **no** `RESOURCE_LOCK` and **no**
`FIXTURES_REQUIRED xvfb_display`. Do not add either — RESEARCH.md marks that an
anti-pattern (inert under a serial gate, and a false record that parallelism was
suspected).

## Shared Patterns

### Bounded X wait (product side, `src/Manager.cpp:913-927`)

**Apply to:** the `timestamp()` fix only.
**Source of the idiom — the codebase already uses check-form reads**
(`src/Events.cpp:539`, VERBATIM, style reference not a proposed edit):
```cpp
    while (XCheckMaskEvent(display(), EnterWindowMask, reinterpret_cast<XEvent*>(e)));
```
**Deadline shape — the harness's own idiom** (`tests/support/WmFixture.h`, `pollUntil`):
```cpp
    template <typename Pred>
    static bool pollUntil(Pred pred, int timeoutMs)
    {
        const auto deadline = Clock::now() + std::chrono::milliseconds(timeoutMs);
        for (;;) {
            if (pred()) return true;
            if (Clock::now() >= deadline) return false;
            pollSleep();
        }
    }
```
Do **not** build a `select()`/thread/`alarm()` scaffold. Do not add a dependency.

### Diagnostic logging (product side, captured by the harness)

**Apply to:** the attribution trace at the blocking branch.
**Convention (project CLAUDE.md, § Error Handling / Logging):** all messages carry
the `wm2: ` prefix; warnings carry `wm2: warning: `; a bounded-wait timeout is a
**warning that falls back to `CurrentTime`**, never `fatal()`.
**Security constraint (RESEARCH.md T-8-REMOTE):** the trace logs a *state word*
only — never a window title, host name or environment value.
**Capture path already exists:** `WmFixture::wmStderr()`
(`tests/support/WmFixture.h:379`):
```cpp
    const std::string& wmStderr() { collectStderr(); return m_stderr; }
```

### Fixture usage in every process-level test

**Apply to:** both new cases.
```cpp
    WmFixture fixture(cleanFixture({/* args */}));   // or bare `WmFixture fixture;`
    x11::DisplayPtr dp = fixture.openDisplay();
    REQUIRE(dp != nullptr);
    Display* d = dp.get();
    parkPointer(d);
```
Available fixture surface (`tests/support/WmFixture.h`): `display()`,
`openDisplay()`, `wmAlive()` (:363), `wmStderr()` (:379), `asanReports()` (:381),
`asanLogPrefix()` (:382), `terminateWmCleanly()` (:369), static `pollUntil()`
(:415). Display isolation is already correct — each fixture reserves its own
display under an exclusive `flock` (`DisplayReservation::tryReserve()`, :173,
pool `:120`–`:199`) and spawns `Xvfb` directly with `-ac -noreset -nolisten tcp`.

### Timing discipline in process-level tests (blocking anti-pattern)

**Apply to:** both new cases.
- `settleWm(d)` — fifteen **spaced** nudges (`tests/test_wm_runtime.cpp:184-189`).
  A tight loop of the same length measurably read stale values.
- `dragSettle()` — 90 ms, `tests/test_wm_geometry.cpp:336-339` — only for
  synthetic input spacing. **Not implicated in this flake** (case #93 failed in
  `mapClientAndAwaitFrame()`, before the first click). Do not widen it.
- `holdFor(ms)` — `tests/test_wm_runtime.cpp:196-200` — deadline loop, never a
  blocking sleep, where elapsed time is itself under test.
- **Rejected outright:** any diff whose only change is a larger number in a
  `sleep_for` or a `constexpr int k*Ms`. Tier misassignment (RESEARCH.md Pitfall 3).

### Mutation discipline (blocking, per `08.5-CONTEXT.md`)

**Apply to:** both new cases.
Delete or invert the production branch the case names, confirm *that* case reddens,
and run the mutation table in **both** the debug tree and the ASan tree
(`bash scripts/gates/build-all.sh asan` — never bare `ctest --test-dir build/asan`,
deferred item 5). 08-12 and 08-13 each found mutations green in debug and fatal
under the sanitizer.

### Guard-observed-failing discipline

**Apply to:** every acceptance criterion in every plan of this round.
Established by plan 08.5-03: run each guard against the pre-edit state, record it
failing with its exact reading, then run it after. An acceptance criterion with no
