**The menu flake's cause is now a deleted line rather than a rate: `findOpenMenu()`'s silent fallback satisfied its own poll on the first iteration with an unrelated window, and removing it makes the two menu configurations produce different dominant pixels for the first time.**

## Accomplishments

- **The four fused stages are separate units, each with its own verdict.** `include/MenuPaint.h` holds the production Expose-to-paint decision; `tests/support/PixelVerdict.h` holds the test instrument's paint-completion decision; `test_menupaint` exercises both with no display, no fixture and no clock. Each of `openRootMenu()`'s three stages now names itself on expiry instead of returning a bare `false`.
- **The completion predicate is positive.** `dominant == expected AND share >= 0.55` replaces `size() >= 2`. Three deterministic cases reproduce three different wrong answers the old rule gave, and they hold on every host forever.
- **The attributed cause is removed.** `findOpenMenu()` returns the window containing the press point or `None`. No timeout, deadline, settle interval or retry was widened — every timing constant in the tree is byte-identical to the round base.
- **The recorded foreign-`Expose` defect is closed.** The modal loop routes it to `eventExposure()` instead of dropping it (ledger entry 9, `src/Buttons.cpp:530`).
- **The discriminator ran thirty times and all thirty passed**, with the two configurations producing *different* dominant pixels 30 times each — where the pre-round measurement had them byte-identical. No reliability claim is made; the arithmetic bounding what thirty passes do and do not establish is stated in the evidence README.

## Deviations from Plan

### 1. [Rule 3 — Blocking] `MenuPaintTarget::None` does not compile

- **Found during:** Task 1
- **Issue:** Xlib defines `None` as a macro (`#define None 0L`), so the enumerator did not survive the preprocessor; the build failed across all three files.
- **Fix:** Renamed the enumerator to `NoTarget`, with a comment naming the collision. The plan's prose ("outer, submenu, foreign, or none") is satisfied.
- **Files:** `include/MenuPaint.h`, `src/Buttons.cpp`, `tests/test_menupaint.cpp`
- **Commit:** `99f6f72`

### 2. [Rule 3 — Blocking] The Expose arm had to be reordered so `Foreign` stays inside the gate's `sed` range

- **Found during:** Task 3
- **Issue:** Task 3's `FOREIGN-DISPATCHED` gate extracts `sed -n '/case Expose:/,/break;/p'`, which stops at the FIRST `break;`. With the `NoTarget` arm placed first, `Foreign` fell outside the range and the gate could not have passed however the code behaved.
- **Fix:** The `Foreign` arm leads the switch. Nothing about the behaviour depends on the order.
- **Files:** `src/Buttons.cpp`
- **Commit:** `00767bb`

### 3. [Rule 2 — Missing critical functionality] The expected colour had to be threaded to five existing call sites

- **Found during:** Task 1
- **Issue:** Four `[wm_menulabel]` cases run with `--menu-background=blue`. Once the verdict became positive at Task 3, a shipped-silver default would have made their paint stage wait out its full 20 s budget and fail. The plumbing was done at Task 1, where it is behaviour-preserving because `classify()` ignores the argument there.
- **Fix:** `openRootMenu()` and `openRootMenuVerified()` take an `expectedBg`; the four cases pass `namedPixel(d, "blue")` and the menu-colour case passes its own `wanted`.
- **Files:** `tests/test_wm_runtime.cpp`
- **Commit:** `99f6f72`

### 4. Task 1's `<files>` list omits `tests/test_wm_runtime.cpp`

- The task's `<action>` mandates rewriting `openRootMenu()`'s third stage, which lives in that file, and the plan-level `files_modified` includes it. Followed the action text.

### 5. Stale comments corrected as Task 3 changed the behaviour they described

- Task 1's comments in `src/Buttons.cpp` and `include/MenuPaint.h` said the `Foreign` verdict was discarded deliberately; Task 3 made that false. Both were rewritten in `00767bb`. `openRootMenuVerified()`'s comment about the fallback it existed to work around was likewise corrected.
