## The finding that reshaped the plan

The plan of record moved X2Go to a v1.1 requirement and amended XDIS-05 down to
three targets, on the reasoning that validating it cost a human session. Three
measurements falsified that before a line was written:

1. `x2goserver 4.1.0.3-5` and `nxagent` were **already installed** — dpkg stamps
   2026-08-29 17:43, during Phase 8's own manual-pass window. Both D-8-X2GO and
   the Phase 8 evidence index said the package "was never installed".
2. `nxagent` runs headless nested on an Xvfb: no client, no SSH, no human.
3. Its extension surface — the thing D-8-X2GO called unknowable without a
   session — is SHAPE, RANDR, RENDER, 23 extensions, and the WM frames clients
   on it.

Total cost: about two minutes. The deviation had been written more
pessimistically than the facts warranted, in the direction that made skipping
the work look better justified.

## TightVNC disproved its own deviation

The more interesting of the two, and the reason validating beats amending.

| Server | Extensions | SHAPE | RANDR | RENDER |
|---|---|---|---|---|
| TigerVNC 1.12.0 | many | yes | yes | yes |
| nxagent 3.5.99.26 | 23 | yes | yes | yes |
| **TightVNC 1.3.10** | **7** | **yes** | **no** | **no** |

D-8-TIGHTVNC argued that a TigerVNC result was genuine evidence about TightVNC,
because both descend from `Xvnc` and their "extension set advertised, Shape
handling, resize handling, the fontconfig picture — substantially overlaps". On
the two extensions that argument named by name, they do not overlap at all.

**The general lesson is the transferable part:** the deviation reasoned from
*ancestry* to *behaviour*. That move is available for any "close relative"
argument about an untested target, and here it was simply wrong.

The result is also the most useful transcript in the project. Until now the
RENDER-less and RANDR-less paths had only ever run behind `WM2_FORCE_NO_*`
levers; they now have a real server behind them. The WM started, both ladders
announced themselves, the client was framed, no protocol errors. The one visible
difference — the client sits at `+21+8` rather than `+24+8` — is `xIndent()`
following the measured tab width as the font ladder drops a rung. The geometry
follows the font, as designed.

## Three findings from the sitting

**1. `destroy-window-delay` was 1500 ms** — upstream wm2's 1997 constant,
carried verbatim and never revisited. Reported as *"way too long ... this is
software for adept people, not for novices."* Now **400 ms**. Not the parser
minimum of 1: the failure is asymmetric, since a false hide costs nothing while
a false delete sends `WM_DELETE_WINDOW` and can lose work, and an ordinary click
runs 50–150 ms.

**2. The appearance.** Redesigned to a silver cool-cast palette, Ubuntu Bold,
and a 1 px bevel on the focused window only. Design parameters from a Fable
subagent; the sideways-tab silhouette untouched. Two judgement calls worth
recording: the gradient the brief asked for was **declined** (across a 21 px tab
the bands read as stripes and quantise badly over VNC), and the bevel shades are
**derived from the configured tab background** rather than hardcoded, so a dark
palette gets bevels that belong to it.

The new `[wm_bevel]` test caught a real ordering bug before it shipped:
`Client::activate()` calls the outgoing client's `deactivate()` *before*
`setActiveClient()` switches, so a window losing focus still reported itself
active and kept its bevel — 68 highlight pixels on a tab that should have had
zero. Fixed by passing the truth `decorate()` already receives.

**3. A correction left unresolved, deliberately.** The operator noted that the
orchestrator's account of the original off-screen-drag defect is "somewhat
inaccurate", while confirming the bug is gone. The specific inaccuracy was not
identified, so the code comment in `src/Client.cpp` and the `08-14-SUMMARY.md`
narrative still carry the orchestrator's version. **Recorded rather than quietly
left:** a plausible-sounding but wrong story in a code comment outlives everyone
who could correct it.

## Performance, asked for and measured

`scripts/stress-exerciser.sh` exists because `[wm_resource_budget]` could not
answer the operator's question. That test maps twenty clients, measures once and
asserts a ceiling — steady-state, and it would pass unchanged against a manager
leaking a kilobyte per window, because it never returns to the same window count
twice. A leak is only visible as a trend across cycles that begin and end in the
same state.

- **Release, 400 windows churned:** RSS 11576 → 11880 kB, **all** growth in the
  first three cycles, then flat — sixteen of the last seventeen cycles moved RSS
  by exactly zero. Descriptors 6 → 6. Zero X errors.
- **ASan/LSan, 120 windows:** RSS climbs ~500 kB/cycle, which is ASan's
  quarantine holding freed memory by design and is **not** a leak signal.
  LeakSanitizer's own verdict: no leaks, only the known `libfontconfig`
  suppression.
- One `X_GetProperty BadWindow` in 520 destroys, ASan only — a client dying
  between the WM deciding to read a property and the server processing it.
  Inherent X11 asynchrony.

~11.9 MB steady state against the 512 MB VPS constraint: about 2.3% of the
target machine.

## Deferred item 18 (from 08.5-01, relevant here)

A title in a script the tab font does not cover renders a correctly-sized,
**blank** tab — CJK measures at 397 px and draws zero pixels of label, because
the tab uses one fontconfig-resolved face and Xft draws nothing for a codepoint
that face lacks. Noto CJK is installed; the WM never asks. A real gap in
VISL-03's promise, deferred to v1.1 with a cheaper partial option costed.
