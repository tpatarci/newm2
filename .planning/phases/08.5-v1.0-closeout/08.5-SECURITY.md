> Per-phase security contract: threat register, accepted risks, and audit trail.

Written after the phase shipped (PR #6, merge commit `0fec5db`), because the ship happened under the
operator's standing carry-through instruction before this review ran; `STATE.md` item 10 records that
order. The register below is the union of the `<threat_model>` blocks of the ten plans that carry one

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| X client → window manager | Client-supplied titles, class hints, states and properties reach the matcher, the tab renderer and the EWMH publisher | Arbitrary bytes, server-allocated; bounded on read |
| Config file → matching and actions | Rule criteria decide which windows receive the four rule actions | Operator-authored text; no action executes anything |
| Validation host → committed repository | Transcripts, window trees, screenshots, sanitizer and gate logs enter a public repository | Window titles, paths; never `~/.xsession-errors`, never addresses or hostnames |
| Remote-desktop servers → window manager | Xvfb, TigerVNC, TightVNC, nxagent each with its own extension set | Only loopback, `-nolisten tcp`, no access-control flag |
| Diagnostic tools → observed process | gdb attach for one backtrace, `/proc` and socket statistics reads | Only the observed WM's own PID and descriptors; integers only written out |
| Test fixtures → host processes | Fixtures start and stop X servers, the WM and clients | Signals sent only to PIDs the fixture itself created |
