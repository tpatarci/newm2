## Carry-forward that will cost time if forgotten

### Test anti-patterns — read before writing any test here

| Anti-pattern | Severity |
|---|---|
| Writing a test that passes without mutating the branch it names | **blocking** |
| Running the mutation table only in debug | **blocking** |
| Tight-loop settles in process-level tests | **blocking** |

- **Every plan from 08-07 through 08-14 found a test that did not test its own
  name.** Delete or invert the production branch and confirm THAT case reddens.
- **Mutate under ASan as well as debug.** 08-12 and 08-13 each found mutations
  green in debug and fatal under ASan.
- **Interactive-input tests need wall-clock spacing, not `pumpWm()`.**
  `Client::move()`'s loop drains every queued event in one sweep and dispatches
  only the last, so an unspaced ButtonRelease is drained alongside the motions
  and the drag silently does nothing. Use `dragSettle()` in
  `tests/test_wm_geometry.cpp` (90 ms, clears the loop's `poll(50ms)`).
- **Guard against vacuous passes.** A frame press is DROPPED unless the client is
  already active, so a drag test can pass having done nothing at all. Use
  `awaitActive()` plus a "did the window actually move" REQUIRE. Measured
  1-in-4 vacuous before that was added.
- **`findFrameChild()` separates tab from button by SIZE, not origin** — they
  share `(0,0)` since the button-target change.
