<objective>
Close the single largest open risk in this phase: on a remote X server without XRender, the WM currently calls its fatal-exit path if the rotated tab font cannot be produced. Spike the actual behaviour, then make the path degrade instead of dying, and prove it against a genuinely RENDER-less server.

Purpose: a window manager that exits on a degraded remote display fails XDIS-04 and XDIS-05 outright — the user gets no window manager at all rather than one with plain labels.
Output: a recorded spike result, a font-degradation ladder in `Border`, RENDER-less end-to-end tests, and the D-14 requirement-wording amendment.
</objective>

    - src/Border.cpp (the `drawLabel()` definition and the destructor's `m_borderCount` refcounted font teardown — both must tolerate a null font)
    - include/x11wrap.h (the rotated and unrotated Xft font factories, and the `XftFontPtr` ownership semantics)
    - src/Manager.cpp (the `fatal()` definition — confirm it terminates the process, which is exactly why the font path must not call it)
    - .planning/phases/08-xrandr-vnc-compatibility-focus-rules/08-PATTERNS.md (the error-handling shared pattern: fatal only for unrecoverable initialisation, `wm2: warning: ` for degraded capability)
    - The Task 1 spike result recorded in this plan's SUMMARY
  </read_first>
  <action>
Rewrite the static font initialisation in `Border` so no font failure can terminate the process. Replace the current two-attempt-then-fatal structure with an explicit ladder, each rung logging a single `wm2: warning: ` line naming which rung was taken so the release-evidence transcript shows the degradation:

1. Rotated font from the preferred chain the code requests today.
2. Rotated font from the generic sans-serif pattern it already falls back to today.
3. **New rung:** an unrotated font from the same preferred chain. Labels then read horizontally rather than sideways — degraded but present and legible.
4. **New rung:** no font at all. The static font pointer stays null, the WM continues, and one warning states that tab labels are unavailable on this display.

Track which rung was taken in a static member so the rest of `Border` can branch on it. Add an accessor for it in `include/Border.h` if `drawLabel()` needs it, following the project's predicate-accessor style.

Then make every consumer of the font null-safe and rung-aware:

- The tab-width computation currently measures a sample glyph's extents. With no font it must fall back to the existing minimum-width floor the code already computes from the tab-top-height constant, so frames still have a sensible tab. With an unrotated font the extents are measured the same way, but be aware the rotated case's zero-height quirk does not apply.
- `drawLabel()` must return early when there is no font, leaving the tab drawn but blank. It must not skip the surrounding frame drawing.
- The destructor's refcounted font teardown must not close a null font.

Keep every code path identical when the preferred rotated font loads, because that is the normal case and the sideways-tab visual identity is non-negotiable.

Cite the decision in a comment in the codebase's established form, referencing that XDIS-04 is satisfied at the fontconfig-fallback level and that reviving core X fonts would undo Phase 4's deliberate removal.
  </action>
