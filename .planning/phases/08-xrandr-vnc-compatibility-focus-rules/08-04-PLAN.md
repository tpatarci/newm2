<objective>
Land the second capability funnel: a single pair of screen-geometry accessors on `WindowManager`, with every existing direct read of Xlib's cached screen dimensions routed through them. Behaviour-preserving, no new features.

Purpose: Xlib's cached screen dimensions never update after a resolution change unless the client calls back into the library. With 16 direct reads scattered across three files, wiring RANDR without this refactor first would leave every one of them silently returning the pre-resize geometry forever. This plan is deliberately separate from 08-05 so one commit is purely mechanical and easy to verify, and the next one adds behaviour.
Output: `screenWidth()` / `screenHeight()` accessors, 16 rewritten call sites, and a geometry test target that pins the pre-refactor values.
</objective>

Declare `int screenWidth() const;` and `int screenHeight() const;` in the public display-accessor block of `include/Manager.h`, immediately after `hasShapeExtension()`, so the two funnels sit side by side as the CONTEXT decisions ask.

Define them in `src/Manager.cpp` as the only two places in the entire codebase that read the manager-owned screen dimensions. Add `m_lastKnownScreenW` and `m_lastKnownScreenH`, initialized to zero in the constructor and seeded from `DisplayWidth`/`DisplayHeight` immediately after `m_root` is established in `initialiseScreen()` — before `setupEwmhProperties()` calls `updateWorkarea()` or writes the initial workarea. Each accessor returns the corresponding member. Add a `// D-27:` comment stating that these are the single source of truth and that plan 08-05 refreshes them from a live root-geometry query after either RANDR or a root ConfigureNotify; direct reads elsewhere are forbidden because Xlib's cache does not self-update on a RANDR-less server.

The two private members belong beside `m_shapeEvent` and are initialized before any path can call the accessors. Plan 08-05 uses them both as the live geometry cache and to coalesce duplicate events; do not initialize them *after* `initialiseScreen()`, because `setupEwmhProperties()` runs inside that function and would otherwise publish an uninitialized workarea.

Then rewrite all 16 direct reads to call the accessors:

- `src/Buttons.cpp` — six reads across three placement computations (menu placement, and the move and resize drag loops). Each currently subtracts 1 from the read; preserve that arithmetic exactly.
- `src/Client.cpp` — six reads across four sites: the pair on the single line inside `manage()`, the two in the fullscreen geometry computation, and the two in `ensureVisible()`. Note these currently pass a hardcoded screen index of 0 while the accessor uses `m_screenNumber`; on this project's single-screen target the two are identical, and routing through the accessor is the correction, not a behaviour change. Reach the accessor through the existing `windowManager()` handle.
- `src/Manager.cpp` — four reads: the pair feeding the initial workarea property and the pair in `updateWorkarea()`.

This is mechanical and behaviour-preserving. Do not adjust any surrounding arithmetic, any variable name, or any conditional. Do not add RANDR anything — no extension query, no event selection, no root event-mask change. Those all belong to plan 08-05, and keeping this commit purely mechanical is the point of splitting the two.
