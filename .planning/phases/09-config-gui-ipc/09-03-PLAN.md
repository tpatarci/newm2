<objective>
Give the running window manager a socket that answers, and get it into both poll sites in one change.

Purpose: this is the phase's central engineering risk, named as such by the research. The event loop
multiplexes exactly two descriptors through a stack-local `struct pollfd fds[2]` declared **twice** —
once in `WindowManager::nextEvent()` and once in `WindowManager::modalWait()`. Every modal grab in
this codebase (the root menu, move, resize, the tab-button hold, the gesture recogniser) funnels
through the second one. A change that reaches only the first produces a window manager that services
the socket when idle and appears to freeze the GUI's live apply the moment a menu is held — the exact
defect class ledger 8 already fixed once for signal delivery. So the two arrays become one shared set
in a single commit, proven by a test that holds a grab and talks to the socket through it.

Output: a header-only descriptor/decision module plus its POSIX implementation, both poll sites
converted, the listening socket started and its path published, hello and status answered, D-16's
access control enforced, and two test binaries — one display-free, one against a real window manager.
</objective>

<decisions_recorded>
Claude's Discretion items from `09-CONTEXT.md`, decided here:

- **DISC-02 — socket path.** `$XDG_RUNTIME_DIR/wm2-born-again/socket<display>`, falling back to
  `/tmp/wm2-born-again-<uid>/socket<display>` exactly as D-16 names. `<display>` is the `DISPLAY`
  string with every character outside `[A-Za-z0-9._-]` replaced by `_`, so `:1` becomes `_1` and a
  concurrent second X display gets its own socket — which is what makes the ctest suite able to run
  window-manager fixtures in parallel at all. Resolution follows `xdgConfigHome()`'s shape exactly:
  read the environment variable, require it be absolute, otherwise take the one documented fallback,
  and chase no other convention.
- **DISC-03 — discovery.** The path is published on the root window as `_WM2_CONFIG_SOCKET`,
  type `XA_STRING`, format 8, written immediately after `_NET_SUPPORTING_WM_CHECK`. A client reads
  the property rather than reconstructing the path, so a window manager started with an unusual
  `XDG_RUNTIME_DIR` is still discoverable.
- **DISC-04 — `SIGHUP`.** Left exactly as it is: `SIGHUP`, `SIGTERM` and `SIGINT` continue to share the
  exit handler. Reload is a socket message and nothing else. The research's recommendation, taken for
  its reason: repurposing `SIGHUP` is a user-visible behaviour change that buys nothing `wm2-ctl
  reload` does not already provide, and D-8.5-01's precedent would require a release-note entry for a
  change with no beneficiary.
- **DISC-06 — modal servicing shape.** Servicing a readable socket descriptor is a **fourth, silent
  case** in the loop, exactly as `ServiceFocusTick` is today: it never returns `ModalWait::Event` and
  never returns `ModalWait::Interrupted`, so no existing caller of `modalWait()` observes any change.
</decisions_recorded>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| any local process -> the listening socket | The phase's new attack surface. Anything that can `connect()` reaches the window manager's own thread. |
| accepted connection -> the protocol dispatcher | Bytes cross into a parser and then into window-manager state. |
| window manager state -> the status reply | Data crosses **out**. D-14 bounds what may cross. |
| filesystem -> the socket path at startup | A path and possibly a pre-existing file, neither necessarily created by this process. |
