<objective>
Make the two fonts this window manager draws with configurable, because today they are not
configurable at all and CGUI-03 requires the GUI to edit fonts.

Purpose: `grep -c -i font src/Config.cpp` returns 0 on this tree. The menu font is a string literal
inside `WindowManager`'s constructor and the tab font is a string literal inside
`Border::loadTabFont()`. Every other thing the Phase 9 GUI edits — nine colours, three focus
booleans, three delays, frame thickness, the new-window command, the shell flag, manual menu entries
— already has a key. Fonts do not. This plan closes that gap, which is simultaneously CONF-02's
outstanding "fonts" box and a precondition for CGUI-03.

Output: two new config keys (`tab-font`, `menu-font`), their two `kOptionSpecs` rows, their two
consumption sites, unit coverage in `tests/test_config.cpp`, runtime differential coverage in
`tests/test_wm_runtime.cpp`, and a release-notes paragraph.
</objective>

<decisions_recorded>
These are Claude's Discretion items from `09-CONTEXT.md`, decided here and binding on every later
plan in this phase. Under D-8.5-01 a key name chosen before v1.0 is free to choose and permanent
after: there will be no deprecated aliases for these.

- **DISC-05 — key names.** `tab-font` and `menu-font`. Chosen over `font-tab`/`font-menu` because every
  existing key in this file is `<subject>-<attribute>` (`tab-foreground`, `menu-highlight`,
  `frame-background`), so `tab-font` sorts and reads with its siblings.
- **DISC-05a — value grammar.** A fontconfig pattern string, handed to `XftFontOpenName` unchanged —
  the same grammar the two hardcoded literals already use. No XLFD, no separate size key: a size key
  would be a second way to say something the pattern already says, and the two could disagree.
- **DISC-05b — defaults.** Each default is the literal the code hardcodes today, so a user with no
  config file sees no change whatsoever.
</decisions_recorded>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| config file -> `Config::applyFile()` | The user's own file, but also a system-wide file a packager may own; both are parsed before any value is used. |
| command line -> `getopt_long()` | Arguments come from whoever starts the session, including a `.xsession` a packager wrote. |
| config value -> `XftFontOpenName` / fontconfig | An arbitrary user string reaches a library parser. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-9-01 | Denial of Service | `Border::loadTabFont()` with an unresolvable `tab-font` | medium | mitigate | The existing four-rung ladder already cannot terminate the process; Task 1 keeps every rung and adds a `[wm_config_runtime]` case that starts the window manager with a deliberately unresolvable pattern and asserts it still frames a client. |
| T-9-02 | Denial of Service | menu font load with an unresolvable `menu-font` | medium | mitigate | The existing generic-sans second rung is kept, so only a host with no sans font at all reaches `fatal()` — the same condition that already ends startup today. Unchanged contract, asserted by a case that starts with a nonsense pattern. |
| T-9-03 | Tampering | an oversized or control-character-laden font pattern in a config file | low | mitigate | `Config::applyFile()` already rejects overlong lines and values (48 cases in `tests/test_config.cpp`); the two new keys are ordinary string settings and inherit that guard without new code. |
| T-9-04 | Information Disclosure | a font pattern containing a filesystem path | low | accept | fontconfig resolves patterns, not paths, and the window manager runs as the user who wrote the value; there is no privilege boundary to cross. Accepted with the reason recorded. |
</threat_model>
