<correction_to_pattern_map>
`09-PATTERNS.md` states that `findOnPath()` in `src/DesktopEntry.cpp` "already exists and is reusable
as-is (it is namespace-free at file scope, not `DesktopEntry::`-qualified per the grep)". **That is
wrong and the plan must not be executed on it.** The function is defined inside the anonymous
namespace that opens near the top of that file and closes below the helper block, so it has internal
linkage and is not reachable from `src/Manager.cpp` at all. Task 1 therefore promotes it into the
`DesktopEntry` namespace and declares it in `include/DesktopEntry.h`, rather than calling something
that cannot be called. Recorded here so the executor does not lose time discovering it as a link
error.
</correction_to_pattern_map>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| PATH -> the window manager's spawn of the GUI | The window manager launches a binary named by an environment variable it did not set. |
| the running session -> committed evidence | A capture on a real machine becomes files in a public repository. |
| the documentation -> a user's expectations | A key documented but not accepted, or accepted but not documented, misleads in opposite directions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-9-51 | Elevation of Privilege | a hostile `wm2-config` earlier on PATH being launched by the Configure entry | medium | accept | PATH is the user's own environment and the window manager runs as that user; anything that can place a binary earlier on their PATH can already run code as them, with or without this menu entry. This is the same disposition the existing `TryExec` handling and the New entry already carry. Accepted, with the reason recorded rather than left implicit. |
| T-9-52 | Denial of Service | the Configure entry spawning a process that becomes a zombie | medium | mitigate | The entry uses the same spawn path the New entry uses, which already carries the reaping guarantee and its `[wm_stress]` assertion; a case in this plan asserts no zombie after selecting the entry. |
| T-9-53 | Information Disclosure | committed evidence carrying a hostname, an address or session error log content | high | mitigate | A verify command greps the evidence tree for this machine's hostname and for session-error-log content and fails on a match; an acceptance criterion repeats it; and it is a standing prohibition in this plan. The repository is public. |
| T-9-54 | Repudiation | a resource claim in the release notes with no measurement behind it | high | mitigate | The figure comes from a recorded run whose evidence names the server, the version and the commit, and there is an automated budget case besides. The research's assumption log explicitly instructed that this measurement not be skipped on the strength of an estimate. |
| T-9-55 | Tampering | documentation drifting from the accepted key set in either direction | medium | mitigate | `scripts/gates/doc-keys.sh` checks both directions and has been shown to fail against a deliberately introduced discrepancy in each. |
| T-9-56 | Denial of Service | a capture process left running after the remote-desktop pass | medium | mitigate | Every process the capture starts is terminated by a PID the capture itself created; killing by name pattern is a standing prohibition in this plan and across the project since 08.5. |
</threat_model>
