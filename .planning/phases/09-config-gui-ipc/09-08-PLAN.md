<objective>
Turn the two binaries and the GUI into two packages a distributor can ship separately, and make the
"the window manager works without GTK" claim a gate rather than a sentence.

Purpose: D-19 asks for two CMake install components so a packager can produce `wm2-born-again` and
`wm2-born-again-config` separately, with the window manager package never depending on GTK. There are
no install rules in this project at all today — `grep '^install(' CMakeLists.txt` is empty — so this
is entirely new build surface. It is also where the invariant the assumption-delta decision accepted
gets implemented: the component, not the binary, is the project's install identity, and the `wm`
component's manifest is where that is checked.

Output: install rules for both components, two desktop entries, a component-manifest gate script, the
GUI-disabled arm added to the build gate, and the packaging section of the release notes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| the build system -> what a package declares as a dependency | Where a GTK dependency could enter the window-manager package unnoticed. |
| an installed desktop entry -> the root menu's spawn path | An installed file becomes something the window manager will offer to execute. |
| the install staging directory -> the filesystem | The gate writes files; where it writes them matters. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-9-46 | Tampering | a GTK dependency entering the `wm` component's install manifest | high | mitigate | The gate script asserts, per executable in the manifest, that no toolkit library is reported. This is the invariant the assumption-delta decision accepted, implemented rather than promised. The acceptance criteria require the gate to be shown failing once against a deliberately broken build. |
| T-9-47 | Tampering | a desktop entry with a command the user did not intend | medium | mitigate | Both entries are files in this repository, reviewed like source; the GUI's entry names the GUI binary and carries a `TryExec` so a missing binary produces no menu entry rather than a failing launch. The existing scanner's filtering is unchanged. |
| T-9-48 | Denial of Service | the install gate writing to a fixed temporary path that another run or another user owns | medium | mitigate | Staging directories live under the build tree, never a fixed path under the system temporary directory — the same rule this project adopted for sanitizer reports for the same reason. Asserted by an acceptance criterion. |
| T-9-49 | Repudiation | a GUI-disabled build certified by a run that silently executed fewer tests | high | mitigate | The gate compares test counts between trees and requires the difference to be fully accounted for by tests that skipped with a stated reason. A standing prohibition in this plan. |
| T-9-50 | Information Disclosure | install-gate logs carrying absolute paths that identify the host | low | mitigate | The gate writes under the build tree and its committed evidence is produced in 09-09, where the standing rule against host identifiers in evidence applies and is checked. |
</threat_model>
